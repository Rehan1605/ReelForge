# V3.6.5 — Multi-user Publication Fan-out

**Date:** 2026-11-01  
**Status:** Implemented and verified in working tree; not committed.

## Objective

Keep duplicate Reel submissions on one processing job and one shared Brain Object while publishing independently to each requesting user's OneNote account.

## Implementation

- `storage/job.py`: merges duplicate requesters atomically while a job remains active, retries insertion if the matching job becomes terminal, and tracks an audience revision for worker race detection. Legacy documents lacking the revision are initialized by MongoDB `$inc` when claimed.
- `processing/publication_fanout.py`: fans publication out independently, persists each user's publication slot, continues after per-user failures, and provides an ownership-checked publication-only retry path.
- `processing/worker.py`: invokes the shared Reel pipeline once, fans out publications, detects requester additions made during processing before completing the job, and handles publication retry jobs without Reel reprocessing.
- `onenote/writer.py`: authenticates after claiming the user's publication slot so unconnected users receive a durable failed slot which can be retried.
- `bot/telegram_bot.py` and `bot/notifier.py`: add `/publish <reel_id>` retry and aggregate publication status guidance.
- `tests/test_v36_publication_fanout.py`: 12 mocked regression tests covering duplicate and concurrent submission, independent per-user pages, partial failure and retry, restart recovery, unconnected accounts, idempotency, audience races, ownership access and per-user Graph client identity.

## Verification

- Full V3 suite: `python -m unittest discover -s tests -p "test_v3*.py"` — 284/284 passed (31.326s).
- Test output includes expected exceptions logged by tests that simulate worker/Mongo/Telegram failures and an existing asyncio ResourceWarning; test run exit status was 0.
- No real Telegram, MongoDB, Microsoft, Instagram, or paid AI service was accessed.

## Compatibility and Known Limits

- No collection or index migration is required. Existing job records without `requesters_version` remain readable; claim-time `$inc` initializes the field. Brain Objects and the established `(reel_id, user_id)` publication slots retain their schema.
- A process crash after Microsoft Graph creates a page but before MongoDB records its page ID remains an unavoidable cross-service atomicity window; Graph page creation and Mongo slot persistence cannot form one transaction. Normal retries are protected by existing slots, but the external-side-effect gap cannot guarantee exactly-once creation.
- Users who have not connected Microsoft remain in the shared requester list and receive failed publication state; they must connect and invoke `/publish <reel_id>` to retry.
