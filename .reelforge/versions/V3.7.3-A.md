# V3.7.3-A — whisper.cpp Transcription Adapter

**Date:** 2026-11-01  
**Status:** Verified in mocked tests; uncommitted  
**Git checkpoint:** Working tree only; no commit created

## Objective

Replace the Python `openai-whisper` inference implementation with local
`whisper-cli`, preserving `transcribe_reel(video_path) -> str` and the existing
pipeline behavior.

## Implementation

- FFmpeg converts source video audio to mono, 16,000 Hz, signed 16-bit PCM WAV.
- Each call receives an isolated temporary directory cleaned on success and
  failure.
- `whisper-cli` uses an explicitly configured multilingual `ggml-base.bin`,
  thread limit, timeout, and documented text-output file flags (`-otxt`, `-of`,
  `-nt`, `-np`). Transcript content is read from the generated `.txt` file,
  never inferred from stdout.
- Timeout handling terminates and waits for the process, then kills and reaps
  it if termination does not complete.
- Errors do not include captured third-party stdout/stderr in application logs.
- Removed `openai-whisper` from `requirements.txt`. Docker PyTorch/libgomp and
  packaging remain unchanged for V3.7.3-B.

## Configuration

- `WHISPER_CPP_BIN` defaults to `whisper-cli`.
- `WHISPER_CPP_MODEL_PATH` is required at transcription time and must name an
  existing `ggml-base.bin`; ReelForge does not download or substitute models.
- `WHISPER_CPP_THREADS` defaults to `2`.
- `WHISPER_CPP_TIMEOUT` defaults to `300` seconds per subprocess.
