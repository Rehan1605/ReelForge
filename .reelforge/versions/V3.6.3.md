## 1. Objective & Motivation

In previous versions (V3.3 through V3.6.2), the Microsoft OAuth callback server (`auth/oauth_server.py`) was designed solely as an ad-hoc local loopback service. It required a human developer to manually run `python -m auth.oauth_server` in a secondary terminal on their laptop. The bind host defaulted to `127.0.0.1`, which prevented cloud container ingress, and the bot runtime (`bot/telegram_bot.py`) had no automated mechanism to start or stop the callback server alongside Telegram polling.

V3.6.3 transforms the OAuth callback server into a production-manageable component:
1. **Configurable Binding**: Allows `OAUTH_HOST` to bind `0.0.0.0` inside containers while defaulting to `127.0.0.1` locally.
2. **Thread-Safe & Idempotent Lifecycle**: Introduces `start_oauth_server()`, `stop_oauth_server()`, and `get_oauth_server()` guarded by `threading.RLock()` to prevent port collisions, duplicate servers, and socket leaks.
3. **Application Hook Integration**: Wires the OAuth callback server directly into the Telegram bot's `post_init` and `post_shutdown` hooks, controllable via the `REELFORGE_START_OAUTH_SERVER` toggle.
4. **Clean Connection Termination**: Emits explicit `Content-Length` and `Connection: close` HTTP headers on all responses (including 404s) to ensure socket teardowns do not block.

## 2. Key Changes

### A. Configuration Layer (`config.py` & `WORKER.env.example`)
- Added `REELFORGE_START_OAUTH_SERVER` environment variable:
  - Defaults to `False` (`"0"`): preserves local development compatibility and existing test assertions.
  - When set to `1` / `"true"`: enables the embedded in-process callback server inside `run_bot()`.
- Documented in `WORKER.env.example` to satisfy worker contract verification.

### B. OAuth Server Lifecycle (`auth/oauth_server.py`)
- Refactored `OAuthCallbackServer`:
  - Uses `threading.RLock()` to guarantee re-entrant safety.
  - Resolves `self._port` in socket initialization to prevent deadlocks during property resolution.
  - Implements thread-safe `stop()` that shuts down the server, closes the socket, and joins the worker thread (`timeout=2.0`) outside the lock.
- Added global singleton lifecycle helpers:
  - `start_oauth_server(host, port, redirect_uri)`: Idempotently starts or returns active server.
  - `stop_oauth_server()`: Safely stops and clears the global server reference.
  - `get_oauth_server()`: Returns active instance or `None`.
- Added `Connection: close` and `Content-Length` headers in `make_callback_handler`.
- Refactored `main()` CLI entrypoint to use the unified lifecycle helpers.

### C. Bot Runtime Hooks (`bot/telegram_bot.py`)
- Extended `run_bot()` to compose dynamic lifecycle hooks:
  - Supports both `REELFORGE_EMBEDDED_WORKER` and `REELFORGE_START_OAUTH_SERVER`.
  - Attaches `post_init` and `post_shutdown` only when active hooks are registered.
- Added `_start_oauth_server_task`:
  - Dynamically inspects `config.OAUTH_STATE_SECRET`. If missing, logs notice and skips startup without crashing bot.
  - Catches port binding errors (`OSError`) and logs warnings without interrupting Telegram bot polling.
- Added `_stop_oauth_server_task`:
  - Gracefully stops the callback server and unbinds socket on bot termination.

## 4. Remaining Cloud Deployment Blockers

1. **Public HTTPS Reverse Proxy / Ingress**: Microsoft Azure AD requires HTTPS for non-loopback redirect URIs. Cloud deployment requires Caddy / Cloudflare Tunnel / Nginx listening on port 443 and proxying to port 8080.
2. **Remote Vision LLM Endpoint**: `OMNIROUTE_BASE_URL` currently defaults to `http://localhost:20128/v1`; remote environment requires valid external OpenAI-compatible API endpoint and API key.
3. **Instagram Cloud Datacenter Ingestion**: Unauthenticated `yt-dlp` on datacenter IPs must be validated; cookie file mounting may be needed if Instagram throttles cloud IPs.
4. **Container Orchestration**: A `docker-compose.yml` or container specification to manage bot, worker, volume mounts, and environment configuration.
