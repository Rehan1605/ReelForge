## Docker architecture

- `whisper-build` compiles the official `ggml-org/whisper.cpp` repository for
  the target platform. It is pinned to v1.9.5 commit
  `d1be6fde11ac6e0407606b4e42fe72d34add8037`.
- `whisper-model` downloads the multilingual `ggml-base.bin` at image-build
  time. Upstream lists the model at about 142 MiB and publishes checksum
  `465707469ff3a37a2b9b8d8f89f2f99de7299dac`; the build verifies that value
  using SHA-1 before copying the model into the runtime image.
- Default final `runtime` target bundles the model at
  `/opt/reelforge/models/ggml-base.bin`. `runtime-base` omits it and supports
  an operator-mounted persistent model directory.
- Runtime contains Python dependencies, `whisper-cli`, FFmpeg, and `libgomp1`;
  it has no compiler toolchain, git, or PyTorch installation. `libgomp1` is
  retained because the CLI is compiled with GGML OpenMP enabled.
- Build stage follows `TARGETPLATFORM` for Linux CPU builds. Cross-architecture
  builds require Buildx native nodes or registered QEMU emulation.

## Startup validation

`validate_transcription_runtime()` checks that `whisper-cli` and FFmpeg are
executable/discoverable, the configured model is readable and named exactly
`ggml-base.bin`, and thread/timeout settings are positive. It does not perform
inference. `processing.worker.validate_worker_runtime()` invokes it for both
launch paths: the standalone worker before workspace activation and the
embedded worker during its bot `post_init`. Bot-only mode does not invoke it.

The current `transcribe_reel` pipeline interface and job contracts are
unchanged. The model stays outside ephemeral Reel workspace directories.

## Deployment notes

- Set `WHISPER_CPP_MODEL_PATH=/opt/reelforge/models/ggml-base.bin` when using
  `.env`/`WORKER.env.example` with the default bundled image; an explicit blank
  env-file value overrides Docker's image ENV.
- The external-model build target requires a persistent read-only mount and
  `WHISPER_CPP_MODEL_PATH` pointing to its `ggml-base.bin` file.
- Each active `whisper-cli` subprocess loads its own model. Begin with one
  worker on small instances. `WHISPER_CPP_THREADS` applies per transcription;
  estimate concurrent CPU threads as worker count times configured threads.
  The operations guide suggests reserving 1 GiB RAM per concurrent transcriber
  as a conservative initial estimate; measure the selected workload/host.
