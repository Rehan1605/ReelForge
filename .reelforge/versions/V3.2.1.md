# ReelForge V3.2.1 — MongoDB Ownership Index Hotfix

> **Release Date**: 2026-09-13
> **Commit**: Included in `87739d9`
> **Engineering Status**: Verified & Committed

---

## 1. Bug Discovered & Root Cause
- In V3.2, a compound index `idx_user_library_active` was defined across `ownership.saved_by` and `ownership.archived_by`.
- In MongoDB, creating a compound index where more than one field is an array (multikey index) violates the engine rule: *"cannot index parallel arrays"*.
- This resulted in startup exceptions on MongoDB Atlas clusters when documents had both arrays populated.

## 2. What Changed & Fix
- Dropped the invalid compound index `idx_user_library_active`.
- Replaced with two separate, valid single-field multikey indexes:
  - `idx_ownership_archived_by` on `ownership.archived_by`
  - `idx_ownership_saved_processed_at` on `ownership.saved_by` and `metadata.processed_at`
- Added automatic self-healing logic in `storage/db.py::ensure_brain_indexes()` that detects and drops the obsolete `idx_user_library_active` index on startup before creating the new ones.
